# 下游整改提示词

这些文件把整体审查的整改计划拆成六个可逐步执行的任务。每个阶段文件本身就是 prompt；可以复制全文交给能读取本仓库的编码助手，或直接要求它读取并执行该文件。**一次只执行一个阶段，不要把整个目录当作一次改动授权。**

审查参考快照为 `master@26452c2bcad7cd0aae216f97440a33a895cffb12`，上游参考基线为 `4947f695955e9e7181c0ea6c9c671704985b2cb0`。这是问题的来源定位，不要求回退或重置当前分支。执行前必须核对最新源码：已经修复的内容跳过并说明证据，无法复现的结论标成待验证，不照抄旧行号修改。

本次规则与提示词文档的存在，不表示六阶段已经执行，也不表示相关运行时场景已经测试。它们与历史开发文档中的原始“Stage 1–5”不是同一轮阶段编号。

## 阶段与依赖

| 阶段 | Prompt | 范围与出口 |
| --- | --- | --- |
| 1 | [规则与测试入口](01-rules-and-test-entry.md) | 校核当前规则、隔离上游 CLA、建立最小有效测试及 CI 入口；不改变应用行为。 |
| 2 | [资源生命周期](02-resource-lifecycle.md) | 修复 capture、窗口、任务栏回调和可选 timer 的退出行为；覆盖关闭与重启交错。 |
| 3 | [媒体会话边界](03-media-session-boundaries.md) | 会话打开刷新、去重所有权失效及选择矩阵测试；保留媒体状态机和 Automatic 行为。 |
| 4 | [版本、CI 与发布](04-version-ci-release.md) | 同 SHA 质量门禁、产物版本与源码追踪、许可材料及 MSIX 路径；不实际发布。 |
| 5 | [当前文档与下游入口](05-current-docs-and-entry-points.md) | 统一现行文档、隐私说明、贡献/下载入口和同步上游清单。 |
| 6 | [Windows 验收与测量](06-windows-validation.md) | 在受控桌面环境检查真实行为及性能，分别记录静态、自动化与人工证据。 |

建议按 1 → 2 → 3 → 4 → 5 → 6 执行。默认从上一阶段已经接受的结果继续；阶段 2/3 依赖阶段 1 的测试入口，阶段 5 以实际实现为准，阶段 6 以待验收构建为准。若阶段未完成或缺少前置输入，明确阻塞，不在后续阶段悄悄补做整个前一阶段。

## 所有阶段共用的执行边界

1. 先读根目录 [AGENTS.md](../../../AGENTS.md)，再读本页与当前阶段要求的实现/文档。开发文档中的历史快照不能代替现状核验。
2. 检查工作树、分支、远程地址及当前 base SHA；保留用户未提交内容和任务材料。不要使用 hard reset、强推或清理目录来获得“干净环境”。
3. 开始前用简短清单说明本阶段要改的文件、问题是否仍存在、验证方式及上游冲突热点。后续按该范围完成，不借机清理整个仓库。
4. 修复、格式和无关清理分开。若用户授权提交/推送/PR，使用阶段专用分支，每个独立问题一个可理解的提交；没有授权则只保留工作区改动和交付说明。不把当前阶段的 PR 授权延伸到所有后续阶段。
5. 不改默认媒体策略，不改声音或视觉质量，不大改 namespace/目录，不批量删除功能、本地化或 Source Generator。依赖升级、行为取舍及新增服务需要单独说明和授权。
6. 不削弱上游隔离、测试或格式规则以便通过检查。可选功能的关闭要考虑共享消费者和在途回调，不能因为一个消费者退出就销毁其他功能仍依赖的资源。
7. 代码变更执行 AGENTS 的 Windows x64 build、solution format 和最终差异检查；有测试项目时运行相关测试并写出实际命令。无 Windows/.NET 环境时可以做静态工作，但必须如实列出未执行项，不能用文档代替回归测试。
8. 新测试要调用实际生产逻辑或通过最小测试接口驱动它，不在测试里复制一份实现来证明“正确”。确定性交错用同步屏障等方式控制，不仅用随机 sleep；测试运行不得联系真实上游 API、购买或发布服务。
9. 不因提示词包含发布步骤就创建 release、移动 tag、使用签名秘密、触发发布 workflow 或合并 PR。提交前检查工作流触发条件；需要会造成这些效果的验证时，单独请求授权。
10. 完成本阶段后交付并停止，不自动进入下一阶段。后续阶段由用户指定，或按用户另行明确授权的连续执行范围开展。

## 每阶段交付格式

- **范围与基线：**当前 SHA、处理的问题、跳过的已修复内容及证据。
- **改动：**文件列表、关键设计选择、为何不用更大范围重构。
- **验证：**逐条列实际命令/结果，区分静态检查、自动化测试、Windows 桌面测试；未运行项写原因。
- **兼容性：**上游热点、原有行为保持情况、迁移与回滚注意事项。
- **剩余项：**未解决问题、需要用户决策/环境的内容，不声称全部整改已完成。
- **版本控制：**若已获授权，附提交及 PR；否则明确未提交。不要把“开 PR”写成“已合入”或“已发布”。

## 使用示例

把下面的路径换成想执行的阶段即可；如需要提交或 PR，请另外明确授权范围。

```text
请读取并执行 docs/development/remediation-prompts/02-resource-lifecycle.md。
只处理本阶段，遵守 AGENTS.md 和提示词索引中的共用边界。
先核验当前实现和前置阶段结果，再修改、补测试并交付。
```
